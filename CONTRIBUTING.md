# Guía de contribución TUI-v4.1


## Requisitos
- Código limpio y documentado.
- Experimentos reproducibles (usa seeds y exporta resultados).
- Documenta cambios en CHANGELOG.md y README.md.
- Mantén la estructura de carpetas y archivos.

## Proceso
1. Haz fork y crea una rama descriptiva.
2. Realiza tus cambios y verifica que los tests pasen.
3. Haz pull request con descripción clara.
4. Responde a comentarios y sugerencias.


- Código bilingüe (ES/EN) en comentarios y docstrings.
- No dejar archivos sueltos en la raíz: usa las carpetas `data/`, `results/`, `docs/`, `sim/`, etc.
- Pinnear dependencias en `requirements.txt`.
- Mantener la cobertura de tests (>99%).
- Documentar cualquier cambio relevante en `CHANGELOG.md`.
- Usar nombres descriptivos para funciones, variables y archivos.
- Seguir el formato de cita y licencias del proyecto.

## Código de conducta / Code of conduct

- Respeto y colaboración internacional.
- No se tolera discriminación, acoso ni lenguaje ofensivo.
- Todas las contribuciones deben ser originales y respetar la licencia Apache 2.0.

## Contribution policy

This repository is public and only the author can edit it directly. No direct edits by third parties are allowed.

If you wish to contribute, you may send suggestions, corrections or ideas by email (jmrgpr@gmail.com) or through GitHub official channels:

- Issues: to report bugs, suggestions or questions.
- Pull requests: will only be accepted if they meet standards and are reviewed by the author.

Acceptance of external changes is not guaranteed. All contributions will be carefully reviewed.

## How to suggest an improvement?

1. Send your suggestion by email to jmrgpr@gmail.com, or
2. Use the Issues section on GitHub to report or propose changes.
3. If you have a technical proposal, you may open a Pull Request, but only the author can approve and merge it.

No direct editing of the repository by third parties is allowed.

## Best practices

- Bilingual code (ES/EN) in comments and docstrings.
- Do not leave loose files in the root: use `data/`, `results/`, `docs/`, `sim/`, etc.
- Pin dependencies in `requirements.txt`.
- Maintain test coverage (>99%).
- Document any relevant change in `CHANGELOG.md`.
- Use descriptive names for functions, variables, and files.
- Follow the project's citation and license format.

## Code of conduct

- Respect and international collaboration.
- Discrimination, harassment, or offensive language will not be tolerated.
- All contributions must be original and respect the Apache 2.0 license.
